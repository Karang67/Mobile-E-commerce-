4. ABSTRACT

In the contemporary retail electronics sector, standalone physical stores face critical challenges competing with centralized multi-vendor e-commerce marketplaces. Local stores often lack real-time digital inventory synchronization, modern payment options, app-like mobile interfaces, and digital certification for the rapidly expanding pre-owned/refurbished smartphone economy.

This project, Shivangi Mobile, presents an enterprise-grade, full-stack omnichannel retail and e-commerce web platform engineered to bridge brick-and-mortar retail with digital commerce. The system implements a client-server architecture featuring:

  1. A High-Performance Frontend: Developed using React 18, TypeScript, Vite, and Tailwind CSS v4, bundled as an installable Progressive Web App (PWA) that operates seamlessly across Android, iOS, Windows, and macOS devices without app-store intermediaries.
  2. Specialized Certified Refurbished Marketplace: Incorporates comprehensive grading tiers (Like New, Superb, Good, Fair), verified battery health indicators, a 32-point quality check (QC) score display, and store warranty tracking.
  3. Omnichannel Payment & Ordering: Provides dynamic UPI QR payment generation, proof screenshot uploads, Cash-on-Delivery (COD) toggles, multi-bank EMI estimation, and one-click WhatsApp automated order dispatch.
  4. Secure Backend REST API: Developed using Node.js and Express.js (ES Modules), secured by Bcrypt password hashing, stateless JSON Web Tokens (JWT), Content Security Policies via Helmet, express-mongo-sanitize to prevent NoSQL injection, and strict rate limiters.
  5. Anti-Tampering Integrity Layer: Features server-side price cross-validation that verifies all submitted order line items against canonical MongoDB database catalog prices, preventing malicious client-side cart tampering.
  6. Cloud Infrastructure: Powered by a MongoDB Atlas cloud database and Cloudinary Content Delivery Network (CDN) for media storage and optimization.

The resulting platform delivers sub-second page loads, complete offline fallback resilience via LocalStorage, zero-latency in-store catalog navigation, and automated order management for regional retailers.

CHAPTER 1: INTRODUCTION & PROBLEM STATEMENT

1.1 Background & Motivation

The global smartphone industry represents one of the fastest-moving consumer technology sectors. In developing economies such as India, tier-2 and tier-3 towns (such as Sumerpur, Pali district, Rajasthan) possess high densities of regional smartphone retail stores. These retailers offer personalized customer relationships, in-person hardware inspections, and instant delivery.

However, consumers increasingly expect digital-first conveniences: browsing specs online, checking certified second-hand inventory, verifying bank EMI options, and paying via Unified Payments Interface (UPI). Without a customized digital platform, local retailers face customer attrition to nationwide e-commerce conglomerates.

1.2 Limitations of Traditional Brick-and-Mortar Retail

  • Information Asymmetry in Pre-Owned Phones: Customers purchasing second-hand phones have no verifiable proof of battery health, internal component testing, or store warranty coverage.
  • Manual Inventory Inefficiencies: Stock levels are tracked in paper ledgers or fragmented spreadsheets, causing out-of-stock discrepancies.
  • Payment Reconciliation Friction: Matching counter UPI payments against orders requires tedious manual verification of transaction slips.
  • No Inherent Web-to-Store Pipeline: Local walk-ins cannot view catalog items beforehand, compare devices side-by-side, or pre-book devices for counter pickup.

1.3 Proposed System & Objectives

The primary objective of Shivangi Mobile is to engineer a localized, resilient, secure omnichannel platform providing:

  1. Universal Multi-Platform Access: A Progressive Web App installable directly from browser viewports with offline caching.
  2. Transparent Refurbished Certification Engine: A standardized 32-point inspection matrix with battery health metrics.
  3. Automated Payment & Verification Pipeline: Dynamic UPI QR rendering, screenshot verification, and tamper-proof server-side calculation.
  4. Direct WhatsApp Bridge: Automatic message generation connecting buyer carts directly to retail personnel.
  5. Role-Based Admin ERP: A secure dashboard to manage orders, inventory, pricing, banners, and store metadata.

1.4 Scope of the Project

The application covers the full product lifecycle for new flagships and certified second-hand electronics (smartphones, tablets, laptops, smartwatches, audio accessories, chargers, power banks), complete order fulfillment, customer inquiries, and administrative oversight for Shivangi Mobile's retail establishment in Sumerpur, Rajasthan.

CHAPTER 4: TECHNOLOGY STACK JUSTIFICATION

4.1 Frontend Technologies

  • React 18 & TypeScript: Enables strict type safety, modular component architecture, and high UI performance through virtual DOM reconciliation.
  • Vite: Offers blazing-fast Hot Module Replacement (HMR) and optimized esbuild bundle generation, outperforming legacy Webpack configurations.
  • Tailwind CSS v4: Uses modern CSS engine features with custom @theme variables (--color-primary-red: #E30613), enabling zero-runtime overhead styling.
  • Leaflet & OpenStreetMap: Lightweight (under 40KB) mapping engine used for rendering the Sumerpur store locator without costly Google Maps API billing.

4.2 Backend & API Technologies

  • Node.js & Express.js (ES Modules): Non-blocking, event-driven I/O engine capable of handling high concurrent traffic while using unified JavaScript/TypeScript syntax across both tiers.
  • Multer: Handles multipart form-data uploads directly in memory buffers before streaming to the CDN.

4.3 Database & Cloud Storage

  • MongoDB Atlas: Highly scalable document database. Its flexible schema natively accommodates varied smartphone specification matrices and variant attributes without complex SQL migrations.
  • Cloudinary CDN: Provides automatic image format optimization (serving WebP/AVIF to supported browsers), responsive downscaling, and edge caching for product photography.

4.4 Authentication & PWA Infrastructure

  • Stateless JWT + Bcrypt: Eliminates server-side session memory overhead while securing administrative endpoints with industry-standard 14-round salted password hashing.
  • vite-plugin-pwa: Auto-generates standard Service Workers and Web Manifests, allowing the web application to be installed directly to home screens as a native application.

CHAPTER 6: SECURITY & DATA INTEGRITY MEASURES

The system implements multiple hardening layers:

  1. SEC-004: Server-Side Price Cross-Validation:
    To prevent clients from modifying item prices in browser developer tools prior to checkout, orderController.js fetches all item IDs from MongoDB and recalculates the total subtotal on the server.
  2. SEC-003: Stateless JWT Admin Authentication:
    Passwords are never stored in plaintext or client cookies. Passwords are salted and hashed with Bcrypt (cost factor: 14). Administrative API routes require verified Bearer tokens.
  3. SEC-010: HTTP Security Headers via Helmet:
    Enforces Content Security Policies (CSP), HSTS (1 year with preload), disables iframe embedding (frameSrc: 'none'), and removes X-Powered-By.
  4. SEC-007: Strict CORS Origin Allowlist:
    Restricts API access to authorized frontend origins (shivangi-mobile.vercel.app and local development ports).
  5. SEC-008: Rate Limiting Defense:
    Applies rate limiters to prevent brute-force attacks on auth, order submissions, and media uploads.
  6. SEC-014: NoSQL Injection Sanitization:
    express-mongo-sanitize strips $ and . characters from incoming request bodies to prevent query operator injection.

  3. Database (MongoDB Atlas): Managed cloud cluster in AWS Mumbai (ap-south-1) with automated failover and daily backups.
  4. Media Storage (Cloudinary CDN): Cloud media bucket (corwtx6y) providing WebP/AVIF compression and global asset delivery.

CHAPTER 11: LIMITATIONS & FUTURE SCOPE

11.1 Limitations

  • Payment screenshot verification currently requires manual admin approval.
  • Map locator utilizes OpenStreetMap tiles, which offer less granular street-level imagery than proprietary paid APIs in certain rural areas.

11.2 Future Scope

  1. Automated Payment Gateway: Integration with Razorpay or Cashfree for automated webhook-based instant payment settlements.
  2. Automated Device Diagnostics: Integration of browser-based WebRTC/Sensor APIs to run automated hardware diagnostics on user trade-in devices.
  3. AI Chatbot: An integrated conversational agent for smartphone recommendations based on customer budgets.
  4. Automated SMS & WhatsApp Alerts: Integration with the Twilio or WhatsApp Business Cloud API for automated dispatch updates.

CHAPTER 12: CONCLUSION

The Shivangi Mobile project successfully demonstrates the design and implementation of a full-stack, omnichannel e-commerce and retail management platform. By combining modern web technologies—React 18, TypeScript, Node.js, Express, MongoDB Atlas, Cloudinary, and PWA capabilities—the system bridges regional retail with modern digital commerce.

The platform provides a secure, responsive, and installable shopping experience for customers while offering store administrators an integrated management portal. The implementation of server-side price verification, NoSQL sanitization, and structured second-hand certification provides a solid foundation for real-world deployment.
